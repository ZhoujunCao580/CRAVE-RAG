# Coverage requirement extension (Planner v0.22)

In addition to deciding decomposition, identify whether the Root or any
SubQuestion requires exhaustive coverage rather than one relevant source.

Use `coverage_requirement: null` when one sufficient source can establish the
answer. Otherwise emit exactly one static requirement on that question:

{
  "required": true,
  "operator": "count | collect_all | top_k | argmax | argmin | complement",
  "scope_text": "<copy the scope phrase from the question>",
  "item_type": "<the unit being counted, collected, or selected>",
  "source_type": "page | table | figure | chart | visual | element",
  "predicate": "<condition an item must satisfy, or null>"
}

For `top_k` only, also emit `"limit": <positive integer>`. Omit `limit`
for every other operator.

Coverage is required when correctness depends on inspecting a complete scope,
including counts, exhaustive lists, top-k selection, extrema, complements, or
claims that no matching item exists. Do not enable it merely because a question
mentions a plural noun.

`scope_text` must preserve the question's wording, such as `the entire
document`, `Pages 18-19`, or `the sensors section`. Do not convert printed page
labels to physical PDF positions. The Environment resolves that namespace and
records any ambiguity.

`item_type` is the answer unit. `source_type` is the kind of document source
that must be enumerated. For example, counting people shown in figures uses
`item_type: "person"` and `source_type: "figure"`. `predicate` is null only
when every enumerated item or source qualifies.

Never invent runtime totals, resolved page IDs, inspected counts, or completion
status. Those belong to the Environment, not the Planner.

This extension replaces the earlier output-shape example. The complete output
shape is now:

{
  "original_question": "<exact input>",
  "subquestions": [
    {
      "subquestion_id": "Q1",
      "text": "<question>",
      "depends_on": [],
      "coverage_requirement": null
    }
  ],
  "coverage_requirement": null
}

Return both coverage fields explicitly, using null when coverage is not
required. The Root requirement belongs at the top level; a SubQuestion's
requirement belongs on that SubQuestion only.
